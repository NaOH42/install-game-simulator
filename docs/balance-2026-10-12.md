# 硬件价格与成长曲线修正

本轮调整硬件与安装工具价格、硬件柜台显示排序，以及数值验证方法。游戏购买价、首装奖励、运行收入、安装工作量和硬件能力保留原值，因此安装等待与资源取舍继续存在。本轮在本地完成验证，没有重新上传 TOY 或更新其他站点。

## 问题与取舍

- 原均衡进阶整套 1,340 点，旗舰整套 15,100 点，价差 11.27 倍；CPU、网络和硬盘的安装速度只从 3.6 增至 12 倍。中段升级预算增长过陡。
- 首次安装红色警戒线后的余额为 280。原双响炮 CPU 售价 240，买完剩 40，仙剑价格 70；即使已运行红警，以 0.2 点/秒产出，也要只等攒钱 150 秒。现在 CPU 190，买完剩 90，可立即买并安装仙剑。
- 所有五类标准进阶型号都不超过 210 点，首次安装后选任何一种，均能保留第二款游戏的 70 点。速度、容量、多开等偏重不同的分支另有价格，不强制一条路线。
- 数值模拟此前强制买齐下一档推荐配置再安装，和实际允许低配安装的规则冲突。新模拟直接通过真实引擎执行，升级预留下一款预算，允许边装边攒。

## 排序与存档

柜台按代际、同档价格和原始索引排序。实际硬件数组、存档中的 `hardware` 与 `ownedHardware` 索引、游戏配置参考均不重排；显示第几行不再作为型号身份。类型参数和收益比较仍不展示。

## 同策略前后对照

旧数据来自本轮修改前 Git HEAD 的六个游戏规则文件，存于独立 `baseline-source/`。前后使用逐字相同的模拟脚本，SHA-256：`2143315fadb3d27edc1363e56d4997399635666b3ad207f841a6a3c65ff24168`。前后都使用固定 1 秒 tick 与真实购买、升级、运行、停止、卸载及安装操作；不强制达到推荐配置。数字为理想及时操作结果，不包含玩家阅读档案和欣赏演出的时间。

三种策略首升均从 185 秒提前至 85 秒；安装与运行收益重叠约占总时长 96%—98%，全 32 款均可完成。最后硬件安装首款仍为 7.09 秒。流水线与自动队列的实际购买时点因资金分配不同而不同，降价不代表所有策略一定更早购买自动队列。

脚本保留旗舰 25—35 分钟的参考目标并输出是否命中，三条路线尚未全部达到。本轮优先修正价格断层、首购资金挤占及选择顺序，不为追时长删减用户希望保留的安装等待。旧强制全套策略的 44.27 分钟结果保存在 `baseline.log`，不能与新模拟混作同比。
