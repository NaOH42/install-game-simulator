# v0.2 运行与资源管理数值

## 可复现标准路线

运行 `pnpm balance`。模拟每秒做一次决策，只使用实际装机点，依次安装 32 款游戏；补齐各代硬件、空间不足时换大盘，在保留下一款购入资金后解锁流水线及自动队列。运行列表按收益与需求效率选择，给安装保留 CPU、内存和网络余量。它是可达性验证，不代表任何玩家的固定通关时间。

当前校准结果：**旗舰目标 44 分 16 秒，32 款全收集 57 分 54 秒**。初始机首装 85 秒，顶配快速型号重装同款 7.09 秒。全流程有 **49 分 46 秒**同时存在安装任务和运行游戏，等待期间持续赚钱。每个阶段按边界精确积分，长后台时间步与短前台时间步结果一致。

| --- | ---: | ---: |
| 首款安装完成，等待玩家运行 | 1:25 | 1 |
| 第一次 CPU 升级 | 3:05 | 2 |
| 全部经典游戏完成 | 10:13 | 8 |

模拟脚本要求旗舰 35—45 分钟、全收集 45—60 分钟，且顶配首款低于 10 秒，所有收集/容量/收入不变量成立。原 v0.1 的 20—30 分钟针对 24 款、无运行管理玩法；本轮时长增加来自更多内容与运行取舍，后段工作量已回调以避免单纯延长等待。

同一购入顺序下，把所有已安装游戏一直全开，模拟全收集需要 **116 分 25 秒**。管理路线在完成瞬间运行 6 款、约 101.2 点/秒；全开路线完成瞬间运行 31 款、约 97.0 点/秒。两者都尚未对最后刚装好的第 32 款执行运行动作。这个比较说明停掉低产出、高占用游戏能改善速度与收益，不是收益奖励不同。

## 资源和收入规则

- 已安装和运行中分开保存；新安装默认停止，玩家执行 `run` 后产出。`stop` 保留文件与收藏，`uninstall` 同时停止运行并释放磁盘。
- `getSystemLoad` 返回 CPU、RAM、GPU、网络的需求、容量与比率。比率 1 表示满载，可以大于 1；RAM 单位为 MB，其余是模拟算力/带宽单位。
- 每款游戏声明 CPU/RAM/GPU/网络需求和 `online`。离线游戏网络需求为 0，不因网络拥塞减收益。
- 收益效率同时取资源拥塞与入门兼容上限的较小值。拥塞部分为所用资源中最紧张的一项 `min(1, capacity / demand)`；入门适配率按每类实际容量除以 `game.min` 所指参考型号容量计算，效率上限为各适配率平方根的最小值。低于入门参考仍可安装运行并持续赚钱，没有硬件等级门槛。
- 低配兼容还增加对应资源需求：`baseDemand × (1 + (1 - fit) × 0.45)`，其中 `fit = min(1, actualCapacity / entryReferenceCapacity)`。因此独自运行、总占用尚未满载，也不能绕过低配代价。入门电脑单开二档《宿舍帝国》效率为 50%，CPU/RAM/GPU 需求也高于正常值；补齐这三类入门参考后恢复 100%。推荐配置只指示升级方向，不额外施加惩罚；磁盘只受真实容量限制。
- 安装同样占用资源：下载申请网络并消耗少量 CPU，解压申请 CPU，写入/校验共享磁盘；所有任务占用内存。运行游戏会争抢这些资源，停止游戏立即释放需求。
- 同时解压/下载的多个任务共享总吞吐；不同阶段也会因辅助 CPU 与内存压力互相影响。GPU 只限制运行游戏，不直接控制文件写入。
- `tick(state, seconds, onIncome)` 只回调实际被动入账；每个阶段时间片按当时运行列表及真实效率分别计算。首装奖励不混入回调。未运行、已停止、已卸载的游戏不继续产生收入。
- `gamePerformance` 返回实际收益、效率、瓶颈与需求。未运行时实际收益为 0，效率是“现在加开它”的预估，便于商店/任务管理器解释低配结果。

## 硬件取舍与兼容

原型号索引 0/1/2 保持原身份，备选追加为 3/4。索引不是强弱等级；UI 与引擎按 `capacity`、`installSpeed`、`slots` 等真实属性判断。

| 类别 | 一种侧重 | 另一种侧重 |
| --- | --- | --- |
| CPU | 高频，解压更快但多开算力较少 | 多核心，多开容量更大但解压较慢 |
| 内存 | 多安装通道 | 较少安装通道，更大运行容量 |
| 硬盘 | 更快写入 | 更大收藏容量 |
| 显卡 | 更多图形算力 | 较少图形算力，但降低运行游戏 CPU 需求 |
| 网络 | 下载更快 | 联网多开容量更大 |

每个型号只付费一次，保存在 `ownedHardware`；已购型号免费换回。购入即换装。换盘必须装得下已安装与已预留容量；换内存必须容纳现有安装通道，失败不扣款。32 款共占用 **122.17 GB**，全收藏需要 160 GB 仓库盘或采取卸载收藏策略，80 GB 快盘依然有速度优势。

## 存档与验证

新玩法使用 `install-simulator.save.v2` / `backup.v2`，经典站点保留 `save.v1` / `backup.v1`。没有新存档时只读迁移旧数据，第一次保存写入新键，旧原始字符串不改动。结构 `version` 保持 1，按新增字段是否存在识别旧格式：旧已安装游戏迁移为运行中，旧当前型号之前的购入链恢复为已购型号。显式不合法的新字段会拒绝，不把损坏字段当缺省值。

迁移保留余额、首装记录、任务阶段和进度，不增加任何离线收入或经过时间。关闭网页不会继续推进；仍打开的后台网页由调用方提供实际经过时间。

核心测试包括：32 款内容完整、首装与顶配反差、低配安装运行、二档低配单开兼容开销与实际入账一致、未运行零收益、停机恢复效率与安装速度、离线游戏免网络惩罚、内存和显卡瓶颈、真实硬件取舍、一次购入免费换装、容量与通道换装拒绝、并行资源共享、阻塞队列跳过、含竞争时长短 tick 等价、精确分游戏入账、旧存档迁移、旧键不覆盖和无离线推进。

以上时间均为自动模拟，浏览器交互与卡顿视觉由根代理实际验收。
